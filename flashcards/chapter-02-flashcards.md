## Chapter 2: Agentic AI: Tool Use, Planning, and Multi-Agent Orchestration — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three phases of a ReAct agent loop iteration? | Thought → Action → Observation. Exam tip: Thought drives tool selection, Action is the tool/function call, Observation is the result fed back into the next Thought. |
| 2 | Key decision criterion: single LLM call vs agent with tools? | Use a single call for one-step, no-external-data tasks needing low latency. Use an agent when the task needs live data, multiple tools, or multi-step decisions. Exam tip: agents add latency/cost overhead — don't pick them by default. |
| 3 | Short-term vs long-term agent memory — core difference? | Short-term = context held within the current session/conversation (e.g., scratchpad, context window). Long-term = persists across sessions, usually stored in a vector DB or knowledge store. Exam tip: pick short-term when persistence isn't required to reduce complexity. |
| 4 | Required field in a function-calling tool schema to define input structure? | 'parameters' — a JSON Schema object specifying argument names, types, and required fields. Exam tip: 'description' tells the model WHEN to use the tool, not its input shape. |
| 5 | RAG as an agentic pattern — what makes it 'agentic'? | The agent decides at reasoning time whether/what to retrieve, invoking retrieval as a tool call rather than always statically stuffing context. Exam tip: static full-context injection is NOT the agentic pattern. |
| 6 | What is NVIDIA NIM? | NVIDIA Inference Microservices — containerized, optimized model inference with a standard (OpenAI-compatible) API, easy to call as a tool in agent frameworks. Exam tip: NIM = serving/inference, not guardrails or orchestration. |
| 7 | What is NeMo Guardrails used for? | Adding programmable rails (topical, safety, jailbreak/injection protection) to LLM-based conversational and agentic systems. Exam tip: distinguish from NIM (inference) and Blueprints (reference architectures). |
| 8 | What are NVIDIA AI Blueprints? | Reference/customizable workflow templates for building specific AI application patterns (e.g., agentic RAG), combining NIM, NeMo components, and orchestration. Exam tip: Blueprints = starting-point architecture, not a runtime service itself. |
| 9 | Multi-agent orchestration — common pattern name? | Planner/orchestrator agent delegates subtasks to specialized worker agents (e.g., retriever agent, coder agent, verifier agent), then aggregates results. Exam tip: orchestration adds coordination overhead — justify it by task decomposition needs. |
| 10 | Common gotcha: agent hallucinates a tool call that doesn't exist. Root cause & mitigation? | Root cause: no schema validation / unclear tool descriptions. Mitigation: strict function schemas, validate calls before execution, use guardrails to reject invalid calls. Exam tip: this is a frequently tested failure mode. |
| 11 | Typical storage mechanism for agent long-term memory? | A vector database storing embeddings of past interactions/facts, retrieved via similarity search when relevant. Exam tip: don't confuse this with short-term context-window memory. |
| 12 | Function calling: what does the model actually return when invoking a tool? | A structured JSON object with the function name and arguments (matching the defined schema) — NOT free text. Exam tip: the calling application executes the function; the model never runs code directly. |
