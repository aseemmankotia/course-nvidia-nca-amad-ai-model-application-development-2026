## Chapter 5: Customization Spectrum: Prompting, RAG, PEFT, and Alignment — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Order customization techniques from cheapest to most expensive | Prompting < RAG < PEFT (LoRA/adapters) < full fine-tuning < full pretraining from scratch. Exam tip: always justify picking the leftmost option that meets requirements. |
| 2 | When does RAG beat fine-tuning for knowledge injection? | When facts change frequently, sourcing/citations are needed, or retraining budget is unavailable. Exam tip: 'daily/weekly updated docs' scenario = RAG, not fine-tuning. |
| 3 | What does LoRA freeze vs. train? | Freezes the original pretrained weights W; trains small low-rank matrices A and B injected as W' = W + BA. Exam tip: base model is unchanged — only adapters are updated. |
| 4 | LoRA rank (r) trade-off? | Higher r = more trainable parameters = more capacity but higher compute/overfitting risk; lower r = fewer params, faster, less expressive. Exam tip: increasing r always increases trainable parameter count. |
| 5 | What is instruction tuning? | Supervised fine-tuning on (instruction, response) pairs that teaches a model to follow natural-language instructions and output formats. Exam tip: changes behavior/format-following, not raw factual knowledge. |
| 6 | RLHF pipeline — list the stages | 1) Supervised fine-tuning (SFT/instruction tuning) 2) Train a reward model on human preference pairs 3) Optimize the policy via RL (e.g., PPO) against the reward model. Exam tip: three distinct stages, reward model required. |
| 7 | DPO vs RLHF — key architectural difference? | DPO optimizes the policy directly on preference pairs with a closed-form loss — no separate reward model or RL loop. Exam tip: DPO is simpler and more stable than RLHF/PPO. |
| 8 | When is prompt engineering the right first choice? | Low data volume, no training budget, task solvable via clear instructions or few-shot examples. Exam tip: always the first technique to attempt before RAG or fine-tuning. |
| 9 | Full fine-tuning vs. PEFT — deployment/storage difference? | Full fine-tuning updates all weights → one full model copy per task (GB-scale). PEFT (LoRA/adapters) stores only small adapter weights (MB-scale) swappable on a shared base model. Exam tip: PEFT enables cheap multi-tenant deployment. |
| 10 | Adapters vs. LoRA — structural difference? | Adapters insert new bottleneck layers with nonlinearities, adding inference latency. LoRA injects low-rank updates that can be merged into existing weight matrices post-training, adding near-zero extra inference latency. Exam tip: LoRA weights are mergeable; adapters are not. |
| 11 | Decision rule: very small dataset (<100 examples), need behavior change not knowledge | Try prompting (few-shot) first; if insufficient, use PEFT (LoRA) rather than full fine-tuning, which typically needs much larger labeled datasets (thousands+ examples). Exam tip: data volume is a primary decision-framework input. |
| 12 | What does alignment (RLHF/DPO) add beyond instruction tuning? | Instruction tuning teaches task-following from demonstrations; alignment further shapes outputs toward human preferences (helpfulness, harmlessness, style) using comparative preference data, applied after SFT. Exam tip: alignment = preference optimization step after instruction tuning. |
