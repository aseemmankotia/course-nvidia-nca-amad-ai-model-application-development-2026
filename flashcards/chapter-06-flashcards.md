## Chapter 6: The Model Landscape: LLMs, Multimodal, Embeddings, and Diffusion — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the core function of self-attention in a transformer? | Computes weighted relevance scores between all tokens in a sequence, letting the model weigh distant context equally to nearby context. Exam tip: self-attention cost scales roughly O(n²) with sequence length — longer context windows cost more compute. |
| 2 | LLM vs Embedding model — primary output difference? | LLM outputs generated text (next-token prediction); embedding model outputs a fixed-size numeric vector representing semantic meaning. Exam tip: use embeddings for search/retrieval, LLMs for generation/reasoning. |
| 3 | What does a diffusion model do at inference time? | Starts from random noise and iteratively denoises it over multiple steps to produce an image matching a text prompt. Exam tip: fewer denoising steps = faster but typically lower-quality output. |
| 4 | Example families of open-weight models. | Llama (Meta), Mistral, Gemma (Google) — weights are downloadable and self-hostable. Exam tip: open-weight = full control and on-prem deployment, but you own fine-tuning and infra costs. |
| 5 | Proprietary/closed model tradeoff. | Accessed via API only (e.g., GPT, Claude, Gemini); no weight access, usage-based cost, vendor manages infra and updates. Exam tip: proprietary = faster to start, less control over data/weights. |
| 6 | Definition of a multimodal model. | A single model that accepts and/or generates more than one modality (text+image, text+audio, etc.) within one architecture. Exam tip: if a scenario needs text AND image understanding in one call, pick multimodal, not two separate models. |
| 7 | Why can't you mix embedding vectors from two different models in one vector index? | Each embedding model produces vectors in its own learned geometric space and dimensionality; mixing models breaks similarity math. Exam tip: re-embed all data with one consistent model whenever you switch embedding models. |
| 8 | Typical embedding vector dimensionality range referenced on the exam. | Commonly a few hundred to a few thousand dimensions depending on model (smaller sentence-embedding models are lower-dimensional, larger proprietary embedding models are higher-dimensional). Exam tip: higher dimensions add nuance but increase storage/compute cost. |
| 9 | Self-attention vs RNN — key architectural advantage tested on exam. | Self-attention processes all tokens in parallel and captures long-range dependencies directly; RNNs process sequentially and struggle with long-range context. Exam tip: this parallelism is why transformers scale better on GPUs. |
| 10 | When should you choose an LLM over an embedding model for a 'search' requirement? | Never for pure retrieval — embeddings are purpose-built for similarity search. Use an LLM only to generate a final answer after retrieval (RAG pattern: embedding model retrieves, LLM generates). |
| 11 | Generic API call pattern for getting an embedding (conceptual). | embedding = embed_model.encode(text) → returns a fixed-length float vector. Exam tip: the function name differs by SDK, but the text-in/vector-out contract is universal across embedding models. |
| 12 | Diffusion model vs GAN — conceptual exam distinction. | Diffusion models generate via iterative denoising (stable training, slower inference); GANs generate via a single generator/discriminator adversarial pass (faster inference, less stable training). Exam tip: most modern text-to-image tools (e.g., Stable Diffusion) are diffusion-based, not GAN-based. |
